# Specification: Atomic SDLC Artifact Standardization

## Goal
Enforce a "Pure Function" philosophy for all `atomic-sdlc` agents by standardizing the filenames used for input/output handshakes. This ensures consistency, predictability, and machine-readability across the SDLC.

## Naming Convention: `[PHASE]_[RESULT].[EXT]`
All artifacts generated by or consumed by atomic commands must follow this pattern:
- **PHASE**: The uppercase name of the master command (e.g., `DISCOVERY`, `DESIGN`, `BUILD`).
- **RESULT**: A clear, noun-based representation of the output.

## Target Mapping

### DISCOVERY Phase
- `:extract` -> `DISCOVERY_REQUIREMENTS.json`
- `:limits` -> `DISCOVERY_CONSTRAINTS.json`
- `:spec` -> `DISCOVERY_SPEC.md`
- `:slice` -> `DISCOVERY_STORIES.json`
- `:criteria` -> `DISCOVERY_CRITERIA.json`
- `:audit` -> `DISCOVERY_AUDIT.json`

### DESIGN Phase
- `:architect` -> `DESIGN_ARCH.md`
- `:data` -> `DESIGN_SCHEMA.[sql|prisma]`
- `:api` -> `DESIGN_API_CONTRACT.[yaml|json]`
- `:ui` -> `DESIGN_UI_SPEC.md`
- `:audit` -> `DESIGN_AUDIT.json`

### BUILD Phase
- `:write` -> Output based on story, but inputs must prioritize `DISCOVERY_STORIES.json`, `DESIGN_SCHEMA.*`, and `DESIGN_API_CONTRACT.*`.
- `:audit` -> `BUILD_AUDIT.json`
- `:integrate` -> `BUILD_INTEGRATION_AUDIT.json`
- `:docs` -> `BUILD_TECHNICAL_DOCS.md`

### VERIFY Phase
- `:write` -> Output based on feature, but inputs must prioritize `DISCOVERY_CRITERIA.json`.
- `:audit` -> `VERIFY_AUDIT.json`
- `:stress` -> `VERIFY_STRESS_REPORT.json`
- `:profile` -> `VERIFY_PROFILE_REPORT.json`

## Technical Constraints
- Every `.toml` file in `commands/atomic/` must be updated.
- "Artifact Discovery" logic in prompts must be updated to prefer these standard names.
- Failures in quality gates (Audits) must output to `[PHASE]_AUDIT.json`.
